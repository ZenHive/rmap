# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`rmap` is a single-binary Rust CLI that manages portable roadmap data (`roadmap/tasks.toml`) for any project, regardless of language. It renders `ROADMAP.md` and `roadmap/data.json` from the TOML source. See `tool_roadmap.md` for the design contract and `AGENTS.md` for additional contributor guidelines.

## Commands

```
cargo build                              # compile
cargo test                               # unit + integration + golden tests
cargo test --test cli                    # run a single test file
cargo test render_command_updates        # run tests matching substring
cargo fmt --check                        # check formatting (rustfmt defaults)
cargo clippy --all-targets -- -D warnings
cargo run -- validate                    # exercise CLI during dev
cargo run -- render --dry
```

Edition is `2024` (Cargo.toml). MSRV: whatever ships with Rust 1.85+.

## Architecture

Pipeline: `tasks.toml` → `schema::Tasks` → either `render_roadmap_str` (markdown) or `export_json_str` (data.json) → write back. Mutations route through `toml_edit` to preserve user formatting and comments.

Module layout:

- `schema.rs` — `serde` structs with `#[serde(deny_unknown_fields)]` on every type. `TaskId` is an `untagged` enum (`Number(u32) | Text(String)`) so task IDs can be either. Custom `PartialEq<u32>` lets numeric IDs compare directly.
- `validate.rs` — parses TOML into `Tasks`, then runs semantic checks: schema_version, statuses, markers, linear_id format (skipped if `[linear]` table absent), timestamp formats (ISO-8601), `blocked_reason` required when `status = "blocked"`, dependency existence, dependency cycles (DFS with back-edge detection), cross-repo relations, phase/bundle reference integrity, and `[focus].phase` matching a declared phase. Errors carry `path:line` location.
- `render.rs` — byte-cursor walk over the input `ROADMAP.md`. Finds `<!-- TASKS:BEGIN phase=N -->` / `<!-- TASKS:END -->` pairs and replaces ONLY the body between them. Bytes outside markers are preserved exactly. The phase number is parsed from the BEGIN marker line.
- `export.rs` — separate `ExportedTask` struct that adds the computed `eff` field for the JSON output. `eff` is never stored in `tasks.toml` or in `schema::Task` — it's derived from `(b+u)/(2d)` and rounded to 2 decimals on emit.
- `mutate.rs` — `rmap status` / `rmap mark` / `rmap depend` paths. All three load with `toml_edit::DocumentMut` (NOT `toml::from_str`) to preserve comments/whitespace, mutate in place, then re-parse through `validate_tasks_str` to reject invalid mutations before the file is written. Bulk status: `update_status_many_str(path, input, ids, new_status)` walks the task array once, matches against a `HashSet`, fails atomically on any unknown ID (no partial write), and re-validates once at the end; `update_status_str` is a thin wrapper around the many-form. `update_markers_str(path, input, id, ops: &[MarkerOp])` walks a single task and applies `+marker`/`-marker` ops left-to-right; adds are idempotent (skip if present), removes are idempotent (skip if absent). `MarkerOp::parse` rejects tokens missing the `+`/`-` prefix. `add_dependency_str(path, input, id, in_repo: Option<&str>, cross_repo: Option<&CrossRepoSpec>)` appends to `depends_on` (in-repo) and/or `cross_repo` (array of inline tables); idempotent on the target id (in-repo) and on the `(repo, task_id, relation)` triple (cross-repo). Cycles, unknown ids, and invalid relations are rejected via post-edit re-validation. `CrossRepoSpec::parse` accepts `<repo>:<task_id>[:<relation>]` with relation defaulting to `"blocks"`.
- `next.rs` — pure selector: highest-Eff `pending` task whose `depends_on` are all `done`, optionally filtered by marker. No I/O. When `[focus].phase` is set, focus-phase candidates win over higher-Eff candidates in other phases; the selector only falls back to other phases when no focus-phase candidate exists.
- `query.rs` — `rmap show` / `rmap list` read paths. `TaskFilter` + `find_task` + `list_tasks` are pure; `format_task` / `format_task_row` produce human stdout. JSON output is delegated to `export.rs` so the agent-contract envelope stays consistent.
- `delegate.rs` — pure `rmap delegate` prompt formatter. It reads a task plus in-repo dependency context and emits structured Markdown for cloud agents; it never mutates files and never calls Linear/GitHub/Slack. `DelegateTarget` (the clap `ValueEnum`) lives here so `format_delegate_prompt` matches on the enum, not a stringified form — silent no-op risk on enum-variant addition is closed at the type level. `append_agent_notes(prompt, target)` emits a target-specific `## Environment notes` section mirroring `~/.claude/includes/cloud-agent-environments.md`.
- `diff.rs` — `rmap diff` engine. `diff_toml(base, current, verbose)` returns a `TomlDiff { metadata, tasks }` envelope (also `Serialize` for `--json`). `diff_metadata` walks scalar/optional/map fields (`schema_version`, `project`, `default_branch`, `linear.team_key`, `linear.workspace_url`, `phases.<key>`, `bundles.<key>`); `diff_tasks` walks the `[[task]]` array. Both emit `Added | Removed | Changed` granularity. Without `--verbose`, only the field-key set that drifted is surfaced (default — matches pre-11b shape). With `--verbose`, Changed entries gain a `values: [{field, before, after}]` array gated by `TASK_VERBOSE_WHITELIST` / `METADATA_VERBOSE_WHITELIST` — verbose values are `serde_json::Value` for shape-agnostic emission, and the array order follows the `diff_fields!` declaration order. `task_map` keys by `TaskId::Display`, so `Number(74)` and `Text("74")` collide across base/current (intentional — authors don't mix forms).
- `schema_json.rs` — emits a JSON Schema for `Tasks` via `schemars` derives on every type in `schema.rs`. The schema covers `tasks.toml` shape, not the `data.json` shape (which adds the computed `eff`).
- `scoring.rs` — shared `efficiency(&Task) -> f64`, `format_efficiency(f64) -> String`, and date helpers (`days_from_civil`, `days_since`, `score_decay_suffix`). All renderers and read commands import from here so the (b+u)/(2d) formula AND the staleness window have a single definition. Date math is pure-integer Howard Hinnant proleptic Gregorian — no chrono dependency.
- `stale.rs` — pure `parse_duration(input)` (parses `7d` / `2w` / `30d` / `1y`) and `find_stale(tasks, max_age_days, today)`. Filters in-progress tasks whose `started_at` is older than the threshold. No I/O.
- `doctor.rs` — `DoctorReport { ok, findings[] }` composite. Aggregates `validate::collect_findings`, `stale::find_stale`, score-decay, degenerate-bundle detection, missing-acceptance_criteria detection, and render drift. `--json` envelope tags variants with `kind: "validate" | "stale" | "score_decay" | "degenerate_bundle" | "missing_acceptance_criteria" | "drift"`. **Always exits 0** — informational only; the strict gates remain `validate` (exit 1) and `validate --check-render` (exit 2). Degenerate-bundle: a `[bundles.<name>]` whose task set equals every `[[task]]` with the same `phase` adds no information beyond the phase. Missing-AC: pending/in_progress tasks with `scores.d >= AC_DIFFICULTY_THRESHOLD (5)` OR `scores.b >= AC_BENEFIT_THRESHOLD (8)` and empty `acceptance_criteria` — thresholds hardcoded; revisit when a real consumer asks for `--ac-threshold`.
- `paths.rs` — walks ancestors of `cwd` to find `roadmap/tasks.toml`. Project root is the directory containing `roadmap/`. CLI flags (`--tasks-path`, `--roadmap-path`, `--data-path`) override discovery.
- `main.rs` — `clap` derive CLI. Top-level `run()` returns `Result<ExitCode>`; specifically `--check-render` returns exit code **2 on render drift** (distinct from exit 1 on validation errors) so pre-commit hooks can distinguish "needs re-render" from "schema broken." `rmap diff` shells out to `git show <ref>:<repo-relative-path>` — diff is read-only on the working tree and a git repo. `rmap mark`'s `ops` positional uses `allow_hyphen_values = true` so `-parallel` is treated as a value, not a flag — as a consequence, named flags (`--tasks-path`, `--roadmap-path`, `--data-path`) must precede the positional `+x`/`-x` tokens on the command line. `rmap depend`'s `on` keyword is a literal optional positional; the runtime rejects anything other than `on` (or `None` when only `--cross-repo` is given).

## Load-bearing invariants

These are easy to violate without breaking tests immediately:

- **Marker boundaries are byte-preserved.** `render` only rewrites bytes between matched `<!-- TASKS:BEGIN phase=N -->` and `<!-- TASKS:END -->`. Everything else — including hand-edited prose, blank lines, the marker lines themselves — is byte-equal in/out. Don't "normalize" the input string anywhere in `render.rs`.
- **`eff` is never persisted.** Don't add it to `schema::Task`. Recompute at render/export time. The schema struct has `#[serde(deny_unknown_fields)]` and would reject it on load anyway.
- **Mutations go through `toml_edit`, not `toml`.** `toml::from_str` + `to_string` would strip comments and reflow formatting. `mutate.rs` uses `DocumentMut` for this reason. New mutator commands (Phase 4+) must do the same.
- **`schema_version = 1` is required.** Refuse to render unknown versions; `validate.rs` emits a `rmap migrate` hint. Bump on any breaking schema change.
- **`linear_id` validation is conditional.** If the `[linear]` table is absent, `linear_id` format is not checked — Linear is opt-in per project.
- **Status / marker / relation enums live as `&[&str]` constants in `validate.rs`** (`VALID_STATUSES`, `VALID_MARKERS`, `VALID_CROSS_REPO_RELATIONS`). Any new value must also be added to the render-time match arms in `render.rs` (status symbols, marker suffixes) — they don't share a source.
- **`schema --json` is the agent self-description boundary (Phase 8).** The schema comes from `schemars` derives on the live `schema::Tasks` types — adding a `#[serde]` rename or a new field changes the schema automatically. Don't hand-author a parallel schema. The CI test `schema_json_command_emits_parseable_schema_for_tasks_file` validates the example `tasks.toml` against the emitted schema; it fails loudly if derive output drifts from serialize output.
- **`--json` outputs of `show` / `list` / `next` / `schema` / `diff` are the agent contract.** Add fields freely; never rename or remove without a `schema_version` bump.
- **`delegate` is read-only and agent-targeted.** It emits Markdown because humans transport the prompt to cloud agents, but the zielgruppe is the target agent. `--to` is an explicit routing override; any stored `assignee` is context, not an enforcement gate.
- **`rmap diff --against` defaults to `current.default_branch`.** Explicit `--against <ref>` overrides. Don't hardcode `"main"`; the loaded TOML is the source of truth for branch naming.
- **`diff::task_changes` per-field comparison is hand-maintained.** When you add a field to `schema::Task`, also add it to the `diff_fields!` invocation in `diff::task_changes` AND to `export::ExportedTask` — otherwise `rmap diff` silently misses the field and `rmap show --json` / `list --json` won't surface it. The macro consolidates the comparisons into one list but is not auto-derived; touch all three files in the same commit when extending `Task`. Decide consciously whether the new field belongs on `TASK_VERBOSE_WHITELIST` in `diff.rs` — whitelist membership is part of the `rmap diff --verbose` agent contract.
- **`rmap diff --verbose` is additive.** Without `--verbose`, `diff` JSON output is byte-identical to pre-11b releases (no `values` key anywhere). With `--verbose`, Changed entries gain `values: [{field, before, after}]` filtered by `TASK_VERBOSE_WHITELIST` / `METADATA_VERBOSE_WHITELIST`. Added/Removed entries always have `values: null` (skipped on serialize). Renaming or removing a whitelist member is a breaking change to the agent contract — bump `schema_version` first.
- **`rmap delegate`'s per-agent footer mirrors `~/.claude/includes/cloud-agent-environments.md`.** That skill include is the source of truth for what Codex/Cursor can reach. `delegate.rs::append_agent_notes` holds inline string literals — when the skill changes (e.g. Codex sandbox gains a new constraint), sync the bullets manually. Tests in `tests/delegate.rs` only assert presence of section header + one target-distinguishing phrase, so phrasing tweaks are safe; structural removal will fail loudly.
- **Top-level `Tasks` fields have the same three-place contract as `Task` fields.** When you add a top-level field to `schema::Tasks` (e.g. `focus`), also extend `diff::diff_metadata` (so `rmap diff` notices add/remove/change) AND `export::ExportedTasks` (so `data.json` surfaces it). The Task-level macro doesn't cover top-level fields; they're walked by hand in `diff_metadata`. Same three-file edit discipline applies.
- **Timestamp fields validate by shape, not semantics.** `created_at`, `started_at`, `done_at`, and `scored_at` are all `Option<String>` validated against the `YYYY-MM-DD` shape (10 chars: 4 digits, dash, 2 digits, dash, 2 digits). Don't promote them to a typed `Date` — the value lives next to user-edited TOML where exact string preservation matters. `9999-99-99` passes the validator on purpose; the error message wording reflects this (it says "must match YYYY-MM-DD format", not "must be an ISO-8601 date").
- **`blocked_reason` is conditionally required.** Whenever `status = "blocked"`, `blocked_reason` must be `Some`. The mutator path (`rmap status <id> blocked`) re-runs validation, so flipping a task to `blocked` without a reason will fail to write.
- **`today_iso()` is the single source of truth for "now".** Reads `RMAP_TODAY` env var first (for deterministic tests), then falls back to `SystemTime::now()`. Any code path that needs today's date — score-decay rendering, `stale`, `doctor` — calls this helper. Tests that exercise date-sensitive behavior MUST set `RMAP_TODAY` on the `Command` env (via `.env("RMAP_TODAY", ...)` on the `Command` builder, or `today.txt` next to the fixture for golden tests). Don't read the system clock directly in new code.
- **`rmap doctor` always exits 0 on success.** It is the soft-signal aggregator, not a gate. The strict gates are `rmap validate` (exit 1 on schema error) and `rmap validate --check-render` (exit 2 on render drift). Doctor only propagates a non-zero exit when `tasks.toml` is fundamentally unparseable — i.e., there is nothing to analyze. CI hooks that want to fail on doctor findings should pipe through jq: `rmap doctor --json | jq -e '.findings | length == 0'`.
- **`DoctorFinding`'s `kind` strings are part of the agent contract.** `validate`, `stale`, `score_decay`, `drift` — same additive rule as `show --json` / `list --json` / `next --json`. Renaming a `kind` value requires a `schema_version` bump. Adding a new variant is fine.
- **Bulk `rmap status 1,2,3 done` is atomic.** All listed IDs must resolve OR no file write happens. The behavior is enforced by validating once at the end of `update_status_many_str` and refusing to emit a partial document. Don't add a "best effort" flag without explicit user request — atomicity is the value proposition over a shell loop.
- **All mutators inherit the validate-then-write contract.** `update_status_*`, `update_markers_str`, and `add_dependency_str` each end with `validate_tasks_str(path, &output)?` BEFORE returning the new string to the caller. The binary then re-parses and re-renders before any file is written. Future mutators (interactive `new`, `new --from-stdin`, anything else in Phase 11b/12) must follow the same shape — never `std::fs::write` the output of a `toml_edit` mutation without round-tripping through `validate_tasks_str` first. The whole point of these helpers is that an invalid mutation (cycle, unknown id, bad marker, bad relation) errors with the file byte-equal to its pre-mutation state.

## Tests

- `tests/cli.rs` — black-box CLI tests via `Command::new(env!("CARGO_BIN_EXE_rmap"))`. Each test gets a unique temp dir from a per-test atomic counter. Date-sensitive tests set `RMAP_TODAY` on the `Command` env (e.g. `.env("RMAP_TODAY", "2026-05-11")`).
- `tests/golden/<case>/` — fixture pairs: `tasks.toml`, `ROADMAP.input.md` (input), `ROADMAP.md` (expected output). Adding a case = drop in a triplet; `tests/render.rs` picks it up. Render-template changes that break expected output fail loudly — that's intended. Optional `today.txt` next to the fixture pins the render date for the runner (otherwise it uses `today_iso()`). Add a `today.txt` to any fixture that uses `scored_at` so it doesn't drift into score-decay over time.
- `tests/roundtrip.rs` — Phase 4 lookahead: parse → `toml_edit` round-trip → assert no spurious diff. Catches comment-preservation regressions before mutation code expands.

## Scope discipline

`tool_roadmap.md` documents the intended phases. Implemented today: validate, render, export json, status (single + bulk), next, show, list, schema, diff, delegate, stale, doctor. Score-decay rendering is automatic on tasks with `scored_at` >30d or missing. Deliberately out of scope (per `tool_roadmap.md`): Linear API calls, web server, git integration beyond `git show <ref>:<path>` for `rmap diff`, shell completions, CI workflow, multi-user sync. Don't add these without checking the roadmap first.
