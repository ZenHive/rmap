# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

One person: the maintainer of a ~20–30-repo portfolio, all driven by rmap roadmaps and dispatched through harness to headless coding agents. Opens the static HTML at a desktop to get a cross-repo overview, then drills into a single project or task.

## Product Purpose

`rmap render --html` (single project) and `rmap render --html --multi` (portfolio) turn `roadmap/tasks.toml` into a human-readable, static, offline page. Success: within seconds the maintainer knows

1. what is dispatchable right now and what is blocked (and why), incl. bottlenecks that unlock the most work;
2. how far each repo / phase / milestone is;
3. how tasks and repos depend on each other (in-repo `depends_on`, `cross_repo` relations);

and can open any task and read and understand its full spec (body, read-first references, acceptance criteria, reviewer checks, out of scope, blocked reason, landing ref, assignee/model, deps).

## Positioning

The roadmap is authored for and consumed by AI agents (harness ingests it; `rmap delegate` turns a task into the agent's prompt). The HTML view is the human's window into that agent-facing contract: the same fields an agent receives, made scannable.

## Operating Context

- Generated by the CLI, opened as a local file; no server, no build step.
- ROADMAP.md stays canonical; the HTML is a snapshot ("static, not live").
- Harness writes status back (`in_progress` + `landing_ref`, `done --verified`, `blocked --reason`).

## Capabilities and Constraints

- Single self-contained file: inline CSS + JS, no CDN, no web fonts; size target < 50 KB per single-project page (excluding data).
- Agent contract, must survive any redesign: `<script id="rmap-data" type="application/json">` island (portfolio adds `rmap-relations`); task cards carry `data-id`, `data-status`, `data-eff`, `data-markers`, `data-depends-on`, `data-phase`; DAG nodes carry `data-id`; phase sections carry `data-phase-status`; portfolio repo rows carry `data-slug`, `data-name`, `data-has-rel`.
- Must print cleanly (`@media print`).
- Terminology: status `pending | in_progress | blocked | done | superseded`; D/B/U scores → Eff = (B+U)/(2D); tier glyphs 🎯 🚀 📋 ⚠️; markers (`parallel`, `handbuild`, `bug`, …); phases, bundles, milestones; `unlocks` = transitive dependents; `dep_layer`.

## Evidence on Hand

27 real roadmaps under `~/_DATA/code/*/roadmap/tasks.toml`, rmap's own included — real content for any render check.

## Product Principles

- Operational first: "what can move now, what is stuck" beats a progress trophy.
- Nothing hidden that an agent would see: every spec field is reachable from the page.
- The view never lies about freshness: it is a dated snapshot.
- Agent contract is invariant; visual layer is free.
